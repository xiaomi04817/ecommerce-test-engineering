# 电商系统 — 需求规格说明书

> 版本: v1.0 | 日期: 2026-06-23 | 项目: 电商测试工程项目

---

## 1. 项目概述

### 1.1 项目背景
本项目为一个**标准电商交易系统**，覆盖用户注册登录、商品浏览搜索、购物车管理、收货地址管理、订单下单及状态流转等核心业务。本项目的主要目标是作为**软件测试能力证明项目**，构建完整的接口测试与自动化测试体系。

### 1.2 系统范围
- **包含**: 用户模块、商品模块、购物车模块、地址模块、订单模块
- **不包含**: 支付网关对接（模拟支付）、物流系统对接（手动状态流转）、商家后台、库存管理后台

## 2. 功能需求

### 2.1 用户模块 (User Module)

| REQ-ID | 功能 | 描述 | 优先级 |
|--------|------|------|--------|
| REQ-U-001 | 用户注册 | 用户通过用户名、密码、邮箱完成注册。用户名唯一，密码长度6-20位 | P0 |
| REQ-U-002 | 用户登录 | 已注册用户通过用户名+密码登录，返回JWT Token | P0 |
| REQ-U-003 | 获取当前用户信息 | 已登录用户获取自己的基本信息（用户名、邮箱、注册时间） | P1 |
| REQ-U-004 | Token过期处理 | JWT Token过期后返回401，前端自动跳转登录页 | P1 |

**业务规则**:
- 用户名: 字母开头，3-20位，字母数字下划线
- 密码: 6-20位，至少包含字母和数字
- 邮箱: 合法邮箱格式
- 密码存储使用 BCrypt 加密

---

### 2.2 商品模块 (Product Module)

| REQ-ID | 功能 | 描述 | 优先级 |
|--------|------|------|--------|
| REQ-P-001 | 商品列表 | 分页返回商品列表（默认每页20条），返回商品ID、名称、价格、库存、图片URL | P0 |
| REQ-P-002 | 商品详情 | 根据商品ID返回商品完整信息（名称、价格、库存、描述、图片列表） | P0 |
| REQ-P-003 | 商品搜索 | 支持按商品名称关键词模糊搜索，支持分页 | P1 |
| REQ-P-004 | 库存校验 | 下单时校验库存是否充足，库存不足返回错误 | P0 |

**业务规则**:
- 商品价格保留两位小数
- 商品库存为非负整数
- 搜索关键词至少2个字符

---

### 2.3 购物车模块 (Cart Module)

| REQ-ID | 功能 | 描述 | 优先级 |
|--------|------|------|--------|
| REQ-C-001 | 查看购物车 | 获取当前用户购物车中所有商品（商品信息+数量+小计） | P0 |
| REQ-C-002 | 添加商品到购物车 | 添加指定商品到购物车，如已存在则数量累加 | P0 |
| REQ-C-003 | 修改购物车商品数量 | 修改购物车中某商品的数量（≥1且≤库存） | P1 |
| REQ-C-004 | 删除购物车商品 | 从购物车中移除指定商品 | P1 |
| REQ-C-005 | 清空购物车 | 下单成功后自动清空已下单商品 | P1 |

**业务规则**:
- 未登录用户不能操作购物车
- 添加商品时校验库存：数量 ≤ 当前库存
- 购物车中商品价格以下单时为准（快照）

---

### 2.4 地址模块 (Address Module)

| REQ-ID | 功能 | 描述 | 优先级 |
|--------|------|------|--------|
| REQ-A-001 | 获取地址列表 | 获取当前用户所有收货地址 | P0 |
| REQ-A-002 | 新增地址 | 添加收货地址（收件人、电话、省市区、详细地址） | P0 |
| REQ-A-003 | 修改地址 | 修改已有收货地址信息 | P1 |
| REQ-A-004 | 删除地址 | 删除指定收货地址（逻辑删除） | P1 |
| REQ-A-005 | 设置默认地址 | 标记某个地址为默认收货地址 | P2 |

**业务规则**:
- 每个用户最多保存10个地址
- 手机号为中国大陆手机号格式（11位，1开头）
- 不能删除已被订单引用的地址（逻辑删除）

---

### 2.5 订单模块 (Order Module)

| REQ-ID | 功能 | 描述 | 优先级 |
|--------|------|------|--------|
| REQ-O-001 | 创建订单 | 提交订单（含商品列表、收货地址），生成订单号，扣减库存 | P0 |
| REQ-O-002 | 获取订单列表 | 分页获取当前用户所有订单（按创建时间倒序） | P0 |
| REQ-O-003 | 获取订单详情 | 根据订单ID获取订单完整信息（商品、金额、状态、地址） | P0 |
| REQ-O-004 | 支付订单 | 模拟支付，将订单状态从"待支付"更新为"已支付" | P0 |
| REQ-O-005 | 发货 | 管理员将订单状态从"已支付"更新为"已发货" | P1 |
| REQ-O-006 | 确认收货 | 用户将订单状态从"已发货"更新为"已收货" | P1 |
| REQ-O-007 | 申请退款 | 用户在"已支付"或"已发货"状态下申请退款 | P1 |
| REQ-O-008 | 退款处理 | 管理员处理退款，状态变为"已退款"，恢复库存 | P1 |
| REQ-O-009 | 取消订单 | 用户在"待支付"状态下可取消订单，恢复库存 | P1 |

**业务规则**:
- 订单号规则: 年月日 + 6位随机数 (如: 20260623-AB3X9K)
- 下单时执行库存扣减（乐观锁控制并发）
- 订单金额 = 商品单价 × 数量 求和（保留两位小数）

## 3. 订单状态机

```
                    ┌──────────┐
          ┌────────→│  待支付   │
          │  (超时)  │ PENDING   │
          │ 自动取消  └────┬─────┘
          │               │ 支付(REQ-O-004)
          │               ↓
          │         ┌──────────┐
          │         │  已支付   │
          │         │  PAID    │
          │         └────┬─────┘
          │              │ 发货(REQ-O-005)
          │  ┌───退款────┼───退款───┐
          │  ↓           ↓          ↓
          │ ┌──────┐ ┌──────────┐  │
          │ │已退款│ │  已发货   │←─┘
          │ │REFUND│ │ SHIPPED  │
          │ └──────┘ └────┬─────┘
          │               │ 收货(REQ-O-006)
          │               ↓
          │         ┌──────────┐
          │         │  已收货   │
          └─────────│RECEIVED  │ (终态)
           (不可能)  └──────────┘
```

**合法状态迁移**:
| 当前状态 | 允许迁移到 |
|---------|-----------|
| 待支付(PENDING) | 已支付(PAID)、已取消(CANCELLED) |
| 已支付(PAID) | 已发货(SHIPPED)、已退款(REFUNDED) |
| 已发货(SHIPPED) | 已收货(RECEIVED)、已退款(REFUNDED) |
| 已收货(RECEIVED) | (终态，不可迁移) |
| 已取消(CANCELLED) | (终态，不可迁移) |
| 已退款(REFUNDED) | (终态，不可迁移) |

**禁止的状态迁移**（测试重点）:
- 待支付 → 已发货 (跳过支付)
- 待支付 → 已收货 (跳过支付+发货)
- 已发货 → 已支付 (逆向流转)
- 已收货 → 任何状态 (终态不可变)
- 已取消 → 任何状态 (终态不可变)

## 4. 非功能需求

| REQ-ID | 类别 | 描述 |
|--------|------|------|
| REQ-NF-001 | 安全 | 所有非登录/注册接口需要JWT Token验证 |
| REQ-NF-002 | 安全 | 密码使用BCrypt加密存储 |
| REQ-NF-003 | 安全 | 用户只能操作自己的购物车、地址、订单 |
| REQ-NF-004 | 数据一致性 | 下单时库存扣减使用乐观锁，防止超卖 |
| REQ-NF-005 | 性能 | 接口响应时间 ≤ 500ms（正常负载） |
| REQ-NF-006 | 数据格式 | 统一响应格式: `{"code": 200, "message": "success", "data": {...}}` |

---

## 5. 模块依赖关系

```
User (JWT认证)
  ↓
Product (商品数据)
  ↓
Cart (需要用户+商品)  +  Address (需要用户)
  ↓                          ↓
  └──────────→ Order ←───────┘
           (需要用户+商品+地址)
```

## 6. 术语表

| 术语 | 说明 |
|------|------|
| JWT | JSON Web Token，用于用户认证 |
| 乐观锁 | 通过版本号(version)控制并发更新 |
| 快照 | 下单时记录当时的商品价格，后续价格变动不影响已有订单 |
| 逻辑删除 | 数据标记为已删除但保留记录 |
