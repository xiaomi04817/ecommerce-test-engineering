## 2. 等价类划分

### 2.1 用户注册 (POST /api/auth/register)

| 字段 | 有效等价类 | 无效等价类 |
|------|-----------|-----------|
| username | 字母开头，3-20位，字母数字下划线 | 空、<3位、>20位、数字开头、含特殊字符、已存在的用户名 |
| password | 6-20位，含字母+数字 | 空、<6位、>20位、纯字母、纯数字、含空格 |
| email | 合法邮箱格式 | 空、无@、无域名、格式错误 |

### 2.2 用户登录 (POST /api/auth/login)

| 字段 | 有效等价类 | 无效等价类 |
|------|-----------|-----------|
| username | 已注册的用户名 | 空、不存在的用户名 |
| password | 正确的密码 | 空、错误的密码、SQL注入尝试 |

### 2.3 商品搜索 (GET /api/products/search)

| 字段 | 有效等价类 | 无效等价类 |
|------|-----------|-----------|
| keyword | ≥2字符的合法关键词 | 空、1个字符、特殊字符、SQL注入 |
| page | ≥1的整数 | 0、负数、非整数、超大值 |
| size | 1-100的整数 | 0、负数、>100 |

### 2.4 购物车添加 (POST /api/cart/items)

| 字段 | 有效等价类 | 无效等价类 |
|------|-----------|-----------|
| productId | 存在且库存>0的商品ID | 空、不存在的ID、库存为0的商品 |
| quantity | 1到库存上限的整数 | 0、负数、超过库存、非整数 |

### 2.5 收货地址 (POST /api/addresses)

| 字段 | 有效等价类 | 无效等价类 |
|------|-----------|-----------|
| receiverName | 2-20位中文或英文 | 空、<2位、>20位、纯数字 |
| phone | 中国大陆11位手机号 | 空、<11位、>11位、非1开头、含字母 |
| province/city/district | 非空字符串 | 空字符串 |
| detail | 5-100位详细地址 | 空、<5位、>100位 |
| isDefault | true / false / 不传 | — |

### 2.6 订单创建 (POST /api/orders)

| 字段 | 有效等价类 | 无效等价类 |
|------|-----------|-----------|
| addressId | 当前用户的有效地址ID | 空、不存在的ID、其他用户的地址ID |
| items[] | 1-N个有效商品（库存充足） | 空数组、库存不足的商品、不存在的商品ID |
| items[].productId | 库存>0的商品ID | 空、不存在的ID |
| items[].quantity | 1到库存上限 | 0、负数、超库存 |

## 3. 边界值分析

### 3.1 用户注册边界值

| 字段 | 边界值测试 |
|------|-----------|
| username长度 | 2(无效)、3(有效)、20(有效)、21(无效) |
| password长度 | 5(无效)、6(有效)、20(有效)、21(无效) |
| 用户名格式 | "a1"(有效)、"1abc"(无效—数字开头)、"a_b"(有效)、"a-b"(无效—特殊字符) |

### 3.2 购物车数量边界值

| 场景 | 边界值 |
|------|--------|
| 添加数量 | 0(无效)、1(有效)、库存数(有效)、库存数+1(无效) |
| 修改数量 | 0(应删除该商品项)、1(有效最小值) |

### 3.3 地址数量边界值

| 场景 | 边界值 |
|------|--------|
| 地址数量上限 | 已有9个地址时添加第10个(有效)、已有10个地址时添加第11个(无效) |

### 3.4 分页边界值

| 字段 | 边界值测试 |
|------|-----------|
| page | 0(无效)、1(有效)、超大值(返回空列表) |
| size | 0(无效)、1(有效)、100(有效)、101(无效) |

### 3.5 订单金额边界值

| 场景 | 边界值 |
|------|--------|
| 商品价格 | 0.01(最小正价格)、0(免费商品—是否支持) |

## 4. 场景法测试

### 场景 S01: 新用户注册登录
```
步骤1: 注册新用户 (POST /api/auth/register)
  → 验证: 返回200, 含用户信息
步骤2: 使用相同用户名再次注册
  → 验证: 返回错误"用户名已存在"
步骤3: 登录 (POST /api/auth/login)
  → 验证: 返回200, 含JWT Token
步骤4: 使用Token获取用户信息 (GET /api/users/me)
  → 验证: 返回用户信息与注册信息一致
```

### 场景 S02: 商品浏览与搜索
```
步骤1: 获取商品列表 (GET /api/products?page=1&size=20)
  → 验证: 返回分页数据, total正确
步骤2: 查看商品详情 (GET /api/products/{id})
  → 验证: 返回商品完整信息
步骤3: 搜索商品 (GET /api/products/search?keyword=手机)
  → 验证: 返回名称含"手机"的商品, 分页正确
```

### 场景 S05: 完整下单链路 (核心场景, Smoke层级)
```
步骤1: 登录获取Token
步骤2: 获取商品列表, 选择有库存的商品
步骤3: 添加商品到购物车 (POST /api/cart/items)
步骤4: 查看购物车 (GET /api/cart) 确认商品已在购物车
步骤5: 新增收货地址 (POST /api/addresses)
步骤6: 创建订单 (POST /api/orders)
  → 验证: 返回订单号, 库存已扣减
步骤7: 查看订单 (GET /api/orders/{id})
  → 验证: 订单状态为"待支付"
步骤8: 支付订单 (PUT /api/orders/{id}/status → paid)
  → 验证: 状态变为"已支付"
步骤9: 发货 (PUT /api/orders/{id}/status → shipped)
  → 验证: 状态变为"已发货"
步骤10: 确认收货 (PUT /api/orders/{id}/status → received)
  → 验证: 状态变为"已收货", 终态不可再变
```

## 5. 状态机测试

### 5.1 订单状态迁移测试 (场景 S06/S07)

| 测试ID | 当前状态 | 操作 | 期望目标状态 | 合法性 |
|--------|---------|------|-------------|--------|
| STM-01 | PENDING | pay | PAID | ✅ 合法 |
| STM-02 | PENDING | cancel | CANCELLED | ✅ 合法 |
| STM-03 | PAID | ship | SHIPPED | ✅ 合法 |
| STM-04 | PAID | refund | REFUNDED | ✅ 合法 |
| STM-05 | SHIPPED | receive | RECEIVED | ✅ 合法 |
| STM-06 | SHIPPED | refund | REFUNDED | ✅ 合法 |
| STM-07 | PENDING | ship | — | ❌ 非法(跳过支付) |
| STM-08 | PENDING | receive | — | ❌ 非法(跳过支付+发货) |
| STM-09 | SHIPPED | pay | — | ❌ 非法(逆向流转) |
| STM-10 | RECEIVED | any | — | ❌ 非法(终态不可变) |
| STM-11 | CANCELLED | any | — | ❌ 非法(终态不可变) |
| STM-12 | REFUNDED | any | — | ❌ 非法(终态不可变) |

### 5.2 库存恢复验证

| 操作 | 库存变化 |
|------|---------|
| 下单成功 | 库存 -N |
| 取消订单(待支付) | 库存 +N |
| 退款完成 | 库存 +N |

## 7. 并发场景测试 (场景 S10)

| 测试ID | 场景 | 描述 | 期望结果 |
|--------|------|------|---------|
| CONC-01 | 重复下单 | 同一请求短时间内发送两次 | 仅创建一个订单，另一次返回错误 |
| CONC-02 | 库存竞态 | 库存为1, 两个用户同时下单(各买1件) | 仅一个成功，另一个返回库存不足 |
| CONC-03 | 库存竞态 | 最后1件库存, 同一用户同时下单+取消 | 最终状态一致（要么订单存在+库存0, 要么订单取消+库存1） |

## 8. 测试数据准备

### 8.1 预置测试数据
- **测试用户**: testuser1 / Test@123456 (已注册)
- **测试商品**: 至少5件商品，价格 0.01 ~ 9999.99，库存 0 ~ 1000
- **零库存商品**: 至少1件库存为0的商品（验证边界）

### 8.2 测试数据隔离
- 每个测试用例独立准备数据
- 测试完成后清理数据（通过 fixture teardown）
- 不依赖特定数据库状态
