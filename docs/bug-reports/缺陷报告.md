## 2. 缺陷详情

#### BUG-001：注册空用户名仍可成功

| 属性         | 内容                    |
| ------------ | ----------------------- |
| **发现日期** | 2026-06-23              |
| **发现阶段** | 功能测试                |
| **测试用例** | TC-U-002-用户名为空注册 |
| **状态**     | 已修复                  |

**复现步骤**：

1. 调用 POST /api/auth/register
2. 传入 `{"username": "", "password": "Pass@123", "email": "test@example.com"}`
3. 观察响应

   **预期结果：** 返回 400，提示"用户名不能为空"

   **实际结果：** 返回 200，注册成功，数据库 `username` 字段为空字符串

   **直接原因：** `RegisterRequest` 类的 `username` 字段缺少 `@NotBlank` 校验注解

   **深层原因：** 后端未统一启用 DTO 参数校验（Controller 方法参数缺少 `@Valid` 注解或 DTO 未定义约束）

   **根本原因：** 开发阶段只关注正向功能实现，遗漏了输入校验层

   **回归验证：** 用户名为空时返回 400，提示"用户名不能为空"，注册被阻止

   **关联**：[[#bug-002]] [[#bug-003]]

#### BUG-006：下单成功但库存未扣减

| 属性         | 内容       |
| ------------ | ---------- |
| **发现日期** | 2026-06-23 |
| **发现阶段** | 冒烟测试   |
| **测试用例** | TC-O-001-有效商品+地址创建订单 |
| **场景**     | S05 完整下单链路 |
| **状态**     | 已修复     |

**复现步骤**：

1. 登录获取 Token
2. 获取商品列表，选择有库存的商品（productId=1）
3. 添加商品到购物车（POST /api/cart/items）
4. 查看购物车（GET /api/cart）确认商品已在购物车
5. 新增收货地址（POST /api/addresses）
6. 创建订单（POST /api/orders）
   → 验证：返回订单号，库存已扣减

   **预期结果：** 订单创建后，`products` 表中对应商品的 `stock` 减少相应数量

   **实际结果：** 订单创建成功（返回 200 + 订单号），但 `stock` 未变化（Python DbHelper 读到陈旧数据）

   **直接原因：** `DbHelper` 使用 PyMySQL 默认 `autocommit=False`，多次查询在同一事务 snapshot 中读到 REPEATABLE READ 隔离级别的陈旧数据，导致测试断言 `old_stock == new_stock`

   **深层原因：** 测试辅助类未考虑 MySQL 事务隔离级别对验证查询的影响

   **根本原因：** DbHelper 连接配置不当，查询应使用 `autocommit=True` 确保每次读取最新已提交数据

   **修复方案：** 在 `DbHelper.__init__()` 的 `pymysql.connect()` 中添加 `autocommit=True`；同步优化 `OrderService.deductStock()` 使用 `updateById` 确保乐观锁正确工作

   **回归验证：** 下单成功后，库存从 100 正确扣减至 98，测试断言 `new_stock == old_stock - 2` 通过

   **关联**：无

#### BUG-007：下单数量为0仍可创建订单

| 属性         | 内容                    |
| ------------ | ----------------------- |
| **发现日期** | 2026-06-23              |
| **发现阶段** | 回归测试                |
| **测试用例** | TC-O-B03-下单数量为0 |
| **状态**     | 已修复                  |

**复现步骤**：

1. 登录获取 Token
2. 准备有效收货地址
3. 调用 POST /api/orders，传入 `{"addressId": 1, "items": [{"productId": 1, "quantity": 0}]}`
4. 观察响应

   **预期结果：** 返回 400，提示"商品数量必须大于0"

   **实际结果：** 返回 200，成功创建了一个含 quantity=0 的订单行项，subtotal=0

   **直接原因：** `OrderService.createOrder()` 未校验 `req.getQuantity() <= 0`

   **深层原因：** 后端只校验了库存是否充足（`stock < quantity`），未校验 quantity 自身的合法性（正值校验委托给了购物车 Controller，订单 Controller 路径缺少等价校验）

   **根本原因：** 缺乏统一的参数校验层，各模块各自校验，存在盲区

   **修复方案：** 在 `OrderService.createOrder()` 的 for 循环中添加 `if (req.getQuantity() == null || req.getQuantity() <= 0) throw new BusinessException("商品数量必须大于0")`

   **回归验证：** 下单 quantity=0 时返回 400，提示"商品数量必须大于0"

   **关联**：[[#bug-008]]

#### BUG-008：下单数量为负数仍可创建订单

| 属性         | 内容                    |
| ------------ | ----------------------- |
| **发现日期** | 2026-06-23              |
| **发现阶段** | 回归测试                |
| **测试用例** | TC-O-B04-下单数量为负数 |
| **状态**     | 已修复                  |

**复现步骤**：

1. 登录获取 Token
2. 准备有效收货地址
3. 调用 POST /api/orders，传入 `{"addressId": 1, "items": [{"productId": 1, "quantity": -1}]}`
4. 观察响应

   **预期结果：** 返回 400，提示"商品数量必须大于0"

   **实际结果：** 返回 200，订单创建成功，但 quantity=-1 导致 `stock - (-1) = stock + 1`，**库存反增1**

   **直接原因：** `OrderService.createOrder()` 未校验 `req.getQuantity() <= 0`

   **深层原因：** `deductStock()` 执行 `product.setStock(stock - quantity)`，当 quantity 为负数时等价于库存增加。下单负数会非法增加库存

   **根本原因：** 缺乏统一的参数校验层，对 quantity 的合法性校验在 OrderService 路径缺失

   **修复方案：** 同 BUG-007，在 `OrderService.createOrder()` 中添加 `quantity <= 0` 前置校验

   **回归验证：** 下单 quantity=-1 时返回 400，拒绝订单

   **关联**：[[#bug-007]]
